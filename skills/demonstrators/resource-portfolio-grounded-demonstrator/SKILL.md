# Resource Portfolio Grounded Demonstrator

Run `uv run ruler workflow resource-portfolio-demonstrator`. This is a hybrid
demonstration: Codex proposes a source-locked formalization, while deterministic
validation and a fresh blind generative critic issue typed findings until the bounded
loop converges or fails closed. Reviewer-approved solver bindings, Z3, HiGHS, the
independent decimal replay, CP-SAT, stress tests, and final explanation retain their
normal authority.

Use `--kb-profile expanded` when the purpose is to stress the knowledge layer. The
expanded profile deterministically appends 32 exact-anchored claims—capability facts,
quantitative requirements, backup policies, positive and negative rules, and a
conjunctive eligibility rule—to the compact dossier. It expands only the candidate KB;
the separately reviewed optimization projection remains deliberately unchanged.
The 43-claim catalogue is split into four deterministic predicate-family partitions.
Before generation, reject any catalogue where a quantitative requirement has no
provider, a backup policy has fewer than two distinct providers, or an expanded
eligibility body has no capability witness. Bind rule-head constants and every body
atom's constants into the deterministic refinement findings so semantic omissions are
repaired before merge.
Run at most two partitions concurrently through the same producer/critic refinement
loop, preserve partition order in receipts, namespace child identifiers, re-anchor
every accepted span against the complete dossier, and compile the merged program as a
whole. The deterministic merge has no provider or solver authority and must be fully
replay-verifiable from its child receipts.

Inspect `accepted_rules.html` for the inherited KB visualization surface. It
must show exact source spans, semantic elements, compiler-validated ASP rules,
predicate dependencies, and projection omissions. Treat it as the pre-acceptance view
over the immutable generated candidate; the adjacent release is publication proof.

Treat every semantic, coverage, compilation, execution, and cross-solver defect as a
typed repair finding. Continue producer/critic/refinement rounds automatically until
the complete candidate passes every gate; do not pause for manual validation and do
not publish a partial KB. Provider or solver availability failures remain explicit
infrastructure failures rather than semantic rejections.

Require the complete accepted KB to exist as backend-native formal programs, not only
as YAML records or snippets embedded in HTML. Write `accepted_kb.lp` through the
canonical Clingo ASP compiler and `accepted_kb.pl` through the Horn-compatible
SWI-Prolog mirror compiler. Run static semantics, execute Clingo, load and query
SWI-Prolog, require exact claim-to-statement closure, and cross-check the grounded
symbolic surfaces. Bind both files byte-for-byte to the typed IR, acceptance decision,
and immutable release; write `accepted_kb_manifest.yaml` and
`formal_logic_release.yaml` and verify deterministic regeneration before publication.

Keep immutable generated candidates as lineage, then automatically accept the complete
logical program only after all deterministic gates pass. Require every accepted
statement to bind to an exact dossier claim and render the report only after replaying
all workflow artifact checks. The accepted KB has logical-runtime authority, while
portfolio optimization remains governed by separate reviewed typed linear rules.

The primary artifact is `build/ruler/resource_portfolio_demonstrator/index.html`.
The adjacent `accepted_rules.html`, `accepted_kb.lp`, `accepted_kb.pl`, acceptance
manifest, release, and YAML evidence provide the rule-lineage graph, active executable
formal KB, and machine-verifiable evidence behind every displayed claim. A successful
run requires a `converged` refinement receipt whose final producer and critic calls are
content-bound. `no_progress`, iteration limits, critic defects, and deterministic
blockers start another semantic refinement round; infrastructure failures block safe
publication without turning an invalid candidate into an accepted KB.

Use `$recommendation-trace-guardian` to certify the argument, then
`$resource-decision-tradeoff-communicator` and `$recommendation-argument-composer` for
the visible report. Use a compact two-state trade-off map—not a decision tree—for the
single policy judgment, followed by a vertical evidence story. Keep a same-model
runner-up distinct from changed-policy sensitivity. Derive the investigated
configuration count from the typed scenario envelope. Leave hashes, receipts, run
identifiers, file inventories, and other replay administration outside the main tab.
